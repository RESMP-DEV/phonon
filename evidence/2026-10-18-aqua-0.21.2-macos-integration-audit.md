## Older-data verdict

Older Aqua data is **not unusable**, but it is not clean acoustic ground truth.

Evidence:

- The 100-clip audit found every cached WAV was mono PCM16 at 16 kHz.
- Median 95% rolloff was about 1.39 kHz and median 99.9% rolloff about 5.07 kHz.
- About 57.4% of mean energy was below 300 Hz.
- Aqua’s application code confirms that history audio is always saved as
  mono PCM16 at 16 kHz, regardless of native or JavaScript provider.
- Its JavaScript fallback explicitly requests `echoCancellation: true` and
  `noiseSuppression: true`, with `autoGainControl: false`.
- Current settings select the native provider, `avalon-v1.1`, deep context,
  privacy mode, and background-audio muting.
- Aqua retains at most 100 local history entries. Its audio directory cleanup
  runs every two hours, uses a three-day retention window, and caps the cache at
  300 MiB with an 80% target.

Practical policy:

1. **Keep old accepted/final text and correction pairs.** They remain useful for
   prompt shape, correction behavior, terminology, and user-specific formatting.
2. **Keep old audio as a degraded-capture pretraining/regularization lane.** It
   can teach robustness to the exact muffled 16 kHz distribution, but it must not
   be the only audio distribution and must not be represented as high-fidelity
   capture.
3. **Do not treat Aqua final text as verified ground truth.** Use it as a strong
   weak label; route disagreement against Cohere, Qwen, and Voxtral to review.
4. **Make native Phonon 48 kHz capture the canonical new lane**, with explicit
   capture-profile provenance and mixture weighting when both lanes are trained.
5. Preserve an untouched future split per capture profile. Do not pool old and
   new scores into one protocol.

## Native macOS bridge

Aqua launches a separate signed Swift executable:

```text
/Applications/Aqua Voice.app/Contents/Resources/resources/AquaMacOSBridge.app
```

It communicates with Electron over:

```text
~/Library/Application Support/Aqua Voice/bridge.sock
```

The Electron supervisor uses a JSON message per `<||EOM||>` frame. It waits for
`<||READY||>`, bootstraps with session/version/config, heartbeats every four
seconds, times out after three missed heartbeats, and restarts with bounded
exponential backoff and a 30-second cooldown. It also kills stray parent-1
copies before launch.

The live bridge process is owned by the Aqua Electron process and holds the
socket. A read-only external socket probe did not receive a response, so this
audit did not assume third-party clients are supported.

## Integration map

| Capability | Aqua implementation | Phonon status / implication |
| --- | --- | --- |
| Global Fn and custom hotkeys | Swift `GlobalKeyboardTap` on CGEvent flags/key events; secure-input and keyboard-layout reconciliation strings | Phonon already has Fn/Right Option CGEvent and Carbon Ctrl+Space fallback. Add secure-input/layout recovery if daily-driver logs show those states. |
| Text insertion | Swift Clipboard plus KeyboardSimulator; AX context validation; NSPasteboard concealed/transient/auto-generated markers; segmented multipart paste; command modes for Enter, Ctrl+Enter, Shift+Enter, Tab, Backspace, waits, and submit preflight | Phonon currently clears the pasteboard, writes text, and posts Command-V. Highest-value parity gap: avoid clipboard history and validate that the target did not change. |
| Per-app behavior | Active-app identity, browser URL extraction, Google Docs caret probe, Notion/Google overrides, Electron AX enabling | Phonon has screen context but not this paste-target contract. Add an app-aware insertion profile after the base clipboard-history fix. |
| Native microphone | Separate Swift bridge uses AVCaptureDevice discovery plus AudioQueue input; emits float chunks and reports device changes | Phonon uses `AVAudioEngine` in the bar process. Keep Phonon native/Swift, but consider AudioQueue or a helper only if measured startup/device stability beats the current path. |
| Mic prestart | JS recorder can keep a prepared microphone and retain a short gesture buffer; native bridge accepts prestart configuration | Phonon already has default-on `instantMic` prewarm and hardware kept warm between utterances. Add a measured early-audio retention comparison. |
| Dual capture paths | Maintains native and JavaScript microphone identities, device matching, exclusions, default/built-in preferences, and automatic reconciliation | Phonon has microphone priority. Add explicit provider/device reconciliation provenance if multiple providers become user-visible. |
| Background audio muting | `SystemAudioManager` caches output device state, mutes or volume-fades default output, verifies state, and restores with retry | Not a Phonon runtime feature. Optional and must be explicit because it changes system state. |
| System audio/camera translation | Separate system-audio capture and camera overlay/system-extension paths | Not core Phonon dictation. Do not copy without separate consent and product scope. |
| Floating UI | Transparent always-ready windows, background throttling disabled, native liquid-glass and window-chrome modules | Phonon has a native SwiftUI pill. Visual effects are lower priority than insertion and audio reliability. |
| Permissions | Microphone via Electron media APIs; screen via desktopCapturer probe; accessibility via trusted-client checks | Phonon already fail-closes permissions. Keep permissions in the native app rather than adding an Electron layer. |

## Prioritized adoption order

1. **Clipboard sovereignty:** set NSPasteboard `org.nspasteboard.ConcealedType`,
   `org.nspasteboard.TransientType`, and `org.nspasteboard.AutoGeneratedType`
   before insertion; preserve/restore prior pasteboard state where possible.
2. **Target validation:** capture frontmost app/AX identity before transcription
   and verify it before posting Command-V; fail visibly if it changed.
3. **App-specific submit behavior:** start with terminal/editor defaults and add
   per-app Enter/Tab/submit profiles only from measured failures.
4. **Capture provenance:** mark every training row as `aqua-cache-16k` or
   `phonon-native-48k`, including provider, selected device, processing flags,
   and resampler identity.
5. **Bridge isolation:** only move hotkey/audio/paste into a helper process if
   the current PhononBar process measurably loses taps or audio startup during
   daily use. Aqua’s design is evidence of viability, not proof of need.
6. **Background-output muting:** leave outside the default product unless the
   owner explicitly wants Aqua-compatible “mute background audio” behavior.
